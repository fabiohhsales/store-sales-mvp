### 3.1 Wave 1 — `5492fe1` (21:57)

**Objetivo:** Transformar o chat do Desk em uma interface estilo WhatsApp com suporte real a todas as formas de mídia.

#### Bugs encontrados e corrigidos nesta wave

**BUG CRÍTICO — Mensagens do AI invisíveis no Desk**  
- **Causa raiz 1:** `calendar-agent.ts` → `sendAndSave()` fazia INSERT em `messages` sem o campo `client_id`.  
- **Causa raiz 2:** `GET /api/desk/conversations/[id]/route.ts` filtrava mensagens com `.eq('client_id', X)`, ignorando silenciosamente todas as linhas sem `client_id`.  
- **Efeito no usuário:** O bot respondia no WhatsApp mas a resposta nunca aparecia no Desk.  
- **Fix 1** (`calendar-agent.ts`): adicionou `client_id: conversation.client_id` ao INSERT.  
- **Fix 2** (`route.ts`): substituiu `.eq('client_id', X)` por `.or('client_id.eq.X,client_id.is.null')` para incluir linhas legadas.

**BUG — Áudio inbound não era armazenado**  
- **Causa:** `normalize-evolution.ts` não capturava `mediaUrl` de mensagens de áudio. Pipeline não incluía `'audio'` na condição de upload.  
- **Fix:** Capturar `audioMessage.url` no normalizador; adicionar `'audio'` ao `if (contentType === 'image' | 'audio' | ...)` no pipeline.

**BUG — `content_type` sempre `'image'` ou `'document'` no envio outbound**  
- **Causa:** `send-media/route.ts` tinha lógica hardcoded que forçava qualquer coisa que não fosse imagem a virar `'document'`, incluindo áudio e vídeo.  
- **Fix:** Ler `mediatype` diretamente do body da requisição e passá-lo sem transformação.

### 3.2 Wave 2 — `443e31a` (22:22)

**Objetivo:** Transcrição de áudio via Whisper, ticks de entrega de mensagens estilo WhatsApp, e atualização de mídia em tempo real sem re-fetch.

#### Bugs encontrados e corrigidos nesta wave

**BUG — Realtime: bolha de áudio/imagem mostrava "indisponível" por ~4 segundos**  
- **Causa:** O evento `INSERT` do Supabase Realtime dispara imediatamente quando a linha é criada, mas o campo `media_url` só é preenchido após o pipeline fazer o upload para o Storage (que pode demorar alguns segundos). O front renderizava a bolha incompleta.  
- **Fix:** Adicionado handler para evento `UPDATE` no canal Realtime do chat. Quando uma linha de mensagem é atualizada (ex.: `media_url` setado pelo pipeline), o front faz merge dos novos campos no estado existente sem refetch.

**BUG — Delivery ticks impossíveis: `evolution_message_id` não era salvo**  
- **Causa:** `sendTextMessage` e `sendMediaMessage` em `evolution.ts` tinham return type `Promise<void>`. Sem o ID de retorno da Evolution, era impossível fazer match quando chegava o evento `messages.update`.  
- **Fix A** (`evolution.ts`): todas as funções de envio agora retornam `Promise<string | null>` (o `key.id` da resposta da Evolution).  
- **Fix B** (`message/route.ts`, `send-media/route.ts`): salvam `evolution_message_id` no INSERT da mensagem.

#### Arquivos modificados na Wave 2

**`src/lib/api/evolution.ts`**  
- Nova interface: `interface EvolutionSendResponse { key?: { id?: string } }`  
- `sendTextMessage`: `Promise<void>` → `Promise<string | null>`  
- `sendMediaMessage`: `Promise<void>` → `Promise<string | null>`  
- `sendMediaByUrl`: agora também retorna `Promise<string | null>`

**`src/lib/bot/pipeline.ts`**

- `saveEvolutionMessage`: chama `transcribeAudio` para tipo `audio`, salva `media_transcript` no DB junto com os outros metadados.

**`src/app/api/webhooks/evolution/route.ts`**

## 7. Arquitetura de Fluxo de Mídia Inbound

```
WhatsApp (Evolution API)
        ↓  webhook messages.upsert
/api/webhooks/evolution/route.ts
        ↓  normalizeEvolutionPayload()
normalize-evolution.ts   ← extrai contentType, mediaUrl, metadata
        ↓
runEvolutionPipeline() em pipeline.ts
  ├── upsert contact + conversation
  ├── uploadMediaToStorage()        ← baixa base64 da Evolution, faz upload para desk-media
  │     └── retorna { storagePath, buffer, resolvedMime }
  ├── transcribeAudio() se audio    ← Whisper, fire-and-forget
  └── INSERT messages com todos os campos incluindo media_transcript
        ↓
Supabase Realtime → chat-view.tsx
  ├── INSERT event → adiciona bolha nova (sem media_url ainda)
  └── UPDATE event → merge media_url + transcript na bolha già existente
```

## 8. Arquitetura de Fluxo de Mídia Outbound (Desk → WhatsApp)

```
chat-view.tsx (Composer)
  ├── Texto → POST /api/desk/conversations/[id]/message
  │     └── sendTextMessage() → salva evolution_message_id na row
  └── Arquivo/Áudio gravado → POST /api/desk/conversations/[id]/send-media
        └── sendMediaMessage() ou sendMediaByUrl() → salva evolution_message_id

Evolution → messages.update webhook
        ↓
handleMessagesUpdate() em route.ts
        ↓
UPDATE messages SET whatsapp_status = ? WHERE evolution_message_id = ?
        ↓
Supabase Realtime UPDATE → chat-view.tsx merge → ticks aparecem
```
